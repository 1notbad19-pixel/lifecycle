\## 1. Введение



\### 1.1 Назначение документа



Настоящая спецификация требований к программному обеспечению (SRS) описывает, что должна делать система «\[Название игры]» — десктопная игра-кликер с элементами тамагочи.



\### 1.2 Область применения продукта



Продукт — настольная одиночная игра, в которой игрок ухаживает за виртуальным питомцем с помощью кликов: кормит, играет, укладывает спать, лечит. Питомец имеет шкалы состояния (голод, счастье, энергия, здоровье), которые меняются со временем. Игра не требует интернета.



\### 1.3 Определения, акронимы и сокращения



| Термин | Определение |

|---|---|

| Питомец | Виртуальное существо, за которым ухаживает игрок |

| Клик | Нажатие на игровой объект (питомца, кнопку действия) |

| Голод | Параметр состояния, растущий со временем |

| Счастье | Параметр состояния, повышаемый играми |

| Энергия | Параметр, расходуемый на действия и восстанавливаемый сном |

| Здоровье | Параметр, снижающийся при плохом уходе |

| Автосохранение | Автоматическая запись состояния в локальный файл |

| SRS | Software Requirements Specification |

| UI | User Interface |

\## 2. Обзор продукта



\### 2.1 Перспектива продукта



«\[Название игры]» — самостоятельное настольное приложение, разрабатываемое в рамках учебного проекта. Технологии: Java, Swing (или JavaFX — укажите, что используете), локальное сохранение в файл. Интернет не требуется.



\### 2.2 Функции продукта



1\. Отображение питомца и его состояния (голод, счастье, энергия, здоровье).

2\. Начисление монет за клики по питомцу.

3\. Действия по уходу: покормить, поиграть, уложить спать, полечить.

4\. Магазин: покупка еды, игрушек, лекарств.

5\. Прогрессия: питомец растёт / эволюционирует при достижении условий.

6\. Автосохранение состояния и загрузка при запуске.

7\. Уведомления о критических состояниях (питомец голоден / болен).

8\. Достижения (опционально).



\### 2.3 Ограничения продукта



\- Только десктоп (Windows/Linux/macOS), без веб и мобильной версии.

\- Java (указать версию, например, 25).

\- Локальное сохранение, без сервера.

\- Один пользователь, без сетевой игры и аккаунтов.

\- Графика двумерная, простая.



\### 2.4 Характеристики пользователей



| Группа | Подготовка | Потребности |

|---|---|---|

| Игрок | Не требуется | Понятное управление, видимый прогресс, простые правила |

| Заказчик/преподаватель | Знание концепции | Возможность проверить требования и критерии приёмки |

| Разработчик | Java, Git | Однозначные требования, воспроизводимая сборка |



\### 2.5 Допущения и зависимости

\## 3. Требования



\### 3.1 Внешние интерфейсы



\#### 3.1.1 Пользовательские интерфейсы



\- \*\*Главный экран:\*\* питомец, шкалы состояния, счётчик монет, кнопки действий (Покормить, Поиграть, Спать, Лечить).

\- \*\*Магазин:\*\* список еды/игрушек/лекарств с ценой и эффектом.

\- \*\*Достижения (опционально):\*\* список достижений и статус.



Ссылки на мокапы: `img/mockup-main.png`, `img/mockup-shop.png`.



\#### 3.1.2 Аппаратные интерфейсы



Специальные устройства не требуются. Взаимодействие — мышь и клавиатура.



\#### 3.1.3 Программные интерфейсы



\- Java Runtime (указать версию).

\- Swing (или JavaFX) для GUI.

\- Локальный файл сохранения (JSON или сериализация).

\- ОС: Windows/Linux/macOS.



\### 3.2 Функциональные требования



\*\*REQ-INT-001 — Отображение главного экрана\*\*

\- Statement: Система должна отображать питомца, шкалы состояния и счётчик монет.

\- Rationale: Игроку нужно видеть состояние питомца и ресурсы.

\- Acceptance Criteria: При запуске видны питомец, 4 шкалы, счётчик монет, кнопки действий.

\- Verification Method: Demonstration, Inspection.



\*\*REQ-INT-002 — Кнопки действий\*\*

\- Statement: Система должна отображать кнопки «Покормить», «Поиграть», «Спать», «Лечить».

\- Rationale: Игроку нужен доступ к уходу.

\- Acceptance Criteria: Все 4 кнопки видны; недоступные действия визуально отличимы.

\- Verification Method: Demonstration.



\*\*REQ-FUNC-001 — Начисление монет за клик\*\*

\- Statement: Система должна увеличивать счётчик монет при клике по питомцу.

\- Rationale: Клик — основной способ заработка.

\- Acceptance Criteria: Один клик увеличивает монеты на 1 (или N по настройке); значение сразу отображается.

\- Verification Method: Test.



\*\*REQ-FUNC-002 — Рост голода со временем\*\*

\- Statement: Система должна увеличивать шкалу голода с течением времени.

\- Rationale: Питомец требует регулярного ухода.

\- Acceptance Criteria: При простое голод растёт; при достижении максимума питомец «голоден».

\- Verification Method: Test.



\*\*REQ-FUNC-003 — Кормление\*\*

\- Statement: Система должна уменьшать голод при кормлении, если у игрока есть еда/монеты.

\- Rationale: Основное действие ухода.

\- Acceptance Criteria: После кормления голод снижается; списывается еда/монеты; при отсутствии ресурсов действие недоступно.

\- Verification Method: Test.



\*\*REQ-FUNC-004 — Игра с питомцем\*\*

\- Statement: Система должна повышать счастье и снижать энергию при игре.

\- Rationale: Второе основное действие ухода.

\- Acceptance Criteria: После игры счастье растёт, энергия падает; при нулевой энергии игра недоступна.

\- Verification Method: Test.



\*\*REQ-FUNC-005 — Сон\*\*

\- Statement: Система должна восстанавливать энергию при сне.

\- Rationale: Энергия нужна для игр.

\- Acceptance Criteria: После сна энергия растёт; во время сна другие действия недоступны.

\- Verification Method: Test.



\*\*REQ-FUNC-006 — Болезнь и лечение\*\*

\- Statement: При низком здоровье питомец «болеет»; лечение восстанавливает здоровье за монеты.

\- Rationale: Дополнительная механика ухода.

\- Acceptance Criteria: При здоровье ниже порога питомец помечается больным; лечение стоит монеты и восстанавливает здоровье.

\- Verification Method: Test.



\*\*REQ-FUNC-007 — Магазин\*\*

\- Statement: Система должна позволять покупать еду, игрушки, лекарства за монеты.

\- Rationale: Расходование заработанных монет.

\- Acceptance Criteria: При достаточном балансе покупка списывает монеты и добавляет предмет; при недостатке — недоступна.

\- Verification Method: Test.



\*\*REQ-FUNC-008 — Автосохранение\*\*

\- Statement: Система должна сохранять состояние в локальный файл при закрытии и периодически.

\- Rationale: Прогресс не должен теряться.

\- Acceptance Criteria: После закрытия и повторного запуска состояние восстанавливается.

\- Verification Method: Test.



\*\*REQ-FUNC-009 — Загрузка состояния\*\*

\- Statement: При запуске система должна загружать корректное сохранение.

\- Rationale: Продолжение игры.

\- Acceptance Criteria: Восстанавливаются монеты, шкалы, инвентарь.

\- Verification Method: Test.



\*\*REQ-FUNC-010 — Валидация сохранения\*\*

\- Statement: Система должна проверять файл сохранения на корректность.

\- Rationale: Повреждённый файл не должен ломать игру.

\- Acceptance Criteria: При некорректном файле — сообщение или запуск с нуля.

\- Verification Method: Test.



\### 3.3 Качество обслуживания



\*\*REQ-PERF-001 — Время запуска\*\*

\- Statement: Приложение должно запускаться не более чем за 3 секунды.

\- Verification Method: Test, Analysis.



\*\*REQ-PERF-002 — Отклик интерфейса\*\*

\- Statement: После клика или действия интерфейс обновляется без заметной задержки.

\- Verification Method: Test, Demonstration.



\*\*REQ-REL-001 — Сохранение после закрытия\*\*

\- Statement: После штатного закрытия последние данные доступны для загрузки.

\- Verification Method: Test.



\*\*REQ-SEC-001 — Обработка ошибок сохранения\*\*

\- Statement: Ошибки чтения/записи обрабатываются без падения.

\- Verification Method: Test.



\### 3.4 Соответствие стандартам



\*\*REQ-COMP-001 — Уникальные ID требований\*\*

\- Statement: Каждое требование имеет уникальный идентификатор.

\- Verification Method: Inspection.



\*\*REQ-COMP-002 — Согласованность ссылок\*\*

\- Statement: Ссылки на мокапы и модель соответствуют файлам в репозитории.

\- Verification Method: Inspection.



\### 3.5 Проектирование и реализация



\*\*REQ-INST-001 — Инструкция по запуску\*\*

\- Statement: В README должна быть инструкция по сборке и запуску.

\- Verification Method: Inspection.



\*\*REQ-BUILD-001 — Воспроизводимая сборка\*\*

\- Statement: Проект собирается стандартной командой (javac / Maven).

\- Verification Method: Demonstration.



\*\*REQ-MAINT-001 — Разделение логики и UI\*\*

\- Statement: Игровая логика отделена от интерфейса (MVC).

\- Verification Method: Inspection.
