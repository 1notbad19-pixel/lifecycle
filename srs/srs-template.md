## 1. Введение

### 1.1 Назначение документа
Настоящая спецификация требований к программному обеспечению (SRS) описывает, что должна делать система MyPet — мобильная игра-кликер с элементами тамагочи.

### 1.2 Область применения продукта
Продукт — мобильная одиночная игра, в которой игрок с помощью кликов ухаживает за виртуальным питомцем (котенком): кормит, играет, укладывает спать, лечит. У питомца есть шкалы состояния (голод, счастье, энергия, здоровье), которые меняются со временем. Игра не требует подключения к интернету.

### 1.3 Определения, акронимы и сокращения

| Термин | Определение |
|---|---|
| Питомец | Виртуальное существо (котенок), за которым ухаживает игрок |
| Клик | Нажатие на игровой объект (питомца, кнопку действия) |
| Голод | Параметр состояния, который со временем увеличивается |
| Счастье | Параметр состояния, который повышается во время игр |
| Энергия | Параметр, который расходуется на действия и восстанавливается во время сна |
| Здоровье | Параметр, который снижается при плохом уходе |
| Автосохранение | Автоматическая запись состояния в локальный файл |
| SRS | Спецификация требований к программному обеспечению |
| UI | Пользовательский интерфейс |

## 2. Обзор продукта

### 2.1 Перспективы продукта
«MyPet» — самостоятельное мобильное приложение, разрабатываемое в рамках учебного проекта. Технологии: Flutter, Dart. Сохранение происходит в локальное хранилище (SharedPreferences). Интернет не требуется.

### 2.2 Функции продукта
1. Отображение питомца и его состояния (голод, счастье, энергия, здоровье).
2. Начисление монет за клики по питомцу.
3. Действия по уходу: покормить, поиграть, уложить спать, вылечить.
4. Магазин: покупка еды (яблок, бананов, рыбы), игрушек, лекарств.
5. Прогрессия: питомец растет / эволюционирует при выполнении определенных условий.
6. Автосохранение состояния и загрузка при запуске.
7. Уведомления о критических состояниях (питомец голоден / болен).
8. Golden Pet — редкий бонусный питомец, появляющийся случайным образом.
9. Звуковое сопровождение событий (клик, кормление, достижение).

### 2.3 Ограничения продукта
- Только мобильная версия (Android 8.0+, iOS 12+), без веб- и десктопной версии.
- Flutter (Dart).
- Локальное сохранение (SharedPreferences), без сервера.
- Один пользователь, без сетевой игры и аккаунтов.
- Графика двухмерная, простая (спрайтовая).

### 2.4 Характеристики пользователей

| Группа | Подготовка | Потребности |
|---|---|---|
| Игрок | Не требуется | Понятное управление, видимый прогресс, простые правила |
| Заказчик/преподаватель | Знание концепции | Возможность проверить требования и критерии приемки |
| Разработчик | Flutter, Git | Четкие требования, воспроизводимая сборка |

## 3. Требования

### 3.1 Внешние интерфейсы

#### 3.1.1 Пользовательские интерфейсы
- **Главный экран:** питомец, шкалы состояния, счетчик монет, кнопки действий (покормить, поиграть, поспать, вылечить).
- **Магазин:** список еды/игрушек/лекарств с ценой и эффектом.
  Ссылки на мокапы: `srs/img/mockup-main.png`, `srs/img/mockup-shop.png`.

#### 3.1.2 Аппаратные интерфейсы
Специальные устройства не требуются. Взаимодействие — сенсорный экран (жесты: тап, свайп).

#### 3.1.3 Программные интерфейсы
- Flutter Runtime (Dart).
- Flutter для графического интерфейса.
- Локальное хранилище SharedPreferences (JSON).
- ОС: Android 8.0+, iOS 12+.

### 3.2 Функциональные требования

**REQ-INT-001 — Отображение главного экрана**
- Утверждение: Система должна отображать питомца, шкалы состояния и счетчик монет.
- Критерии приемки: при запуске видны питомец, 4 шкалы, счетчик монет, кнопки действий.
- Метод проверки: демонстрация, осмотр.

**REQ-INT-002 — Кнопки действий**
- Утверждение: система должна отображать кнопки «Покормить», «Поиграть», «Спать», «Лечить».
- Критерии приемки: видны все 4 кнопки; недоступные действия визуально различимы.
- Метод проверки: демонстрация.

**REQ-FUNC-001 — Начисление монет за клик**
- Утверждение: Система должна увеличивать счетчик монет при клике на питомца.
- Критерии приемки: один клик увеличивает количество монет на 1; значение отображается сразу.
- Метод проверки: тест.

**REQ-FUNC-002 — Рост голода с течением времени**
- Утверждение: система должна увеличивать шкалу голода с течением времени.
- Критерии приемки: при простое голодание растет; при достижении максимума питомец «голоден».
- Метод проверки: тест.

**REQ-FUNC-003 — Кормление**
- Утверждение: Система должна уменьшать голод при кормлении, если у игрока есть еда/монеты.
- Критерии приемки: после кормления голод уменьшается; еда/монеты списываются; при отсутствии ресурсов действие недоступно.
- Метод проверки: тест.

**REQ-FUNC-004 — Игра с питомцем**
- Утверждение: Система должна повышать уровень счастья и снижать уровень энергии при игре.
- Критерии приемки: после игры уровень счастья повышается, уровень энергии снижается; при нулевом уровне энергии игра недоступна.
- Метод проверки: тест.

**REQ-FUNC-005 — Сон**
- Утверждение: Система должна восстанавливать энергию во время сна.
- Критерии приемки: После сна энергия восстанавливается; во время сна недоступны другие действия.
- Метод проверки: тест.

**REQ-FUNC-006 — Болезнь и лечение**
- Утверждение: при низком уровне здоровья питомец «болеет»; лечение восстанавливает здоровье за монеты.
- Критерии приемки: при уровне здоровья ниже порогового питомец помечается как больной; лечение стоит монет и восстанавливает здоровье.
- Метод проверки: тест.

**REQ-FUNC-007 — Магазин**
- Утверждение: система должна позволять покупать еду, игрушки, лекарства за монеты.
- Критерии приемки: при достаточном балансе покупка списывает монеты и добавляет предмет; при недостатке — недоступна.
- Метод проверки: тест.

**REQ-FUNC-008 — Автосохранение**
- Утверждение: Система должна сохранять состояние в локальном файле при закрытии и периодически.
- Критерии приемки: После закрытия и повторного запуска состояние восстанавливается.
- Метод проверки: тест.

**REQ-FUNC-009 — Загрузка состояния**
- Утверждение: При запуске система должна загружать корректное сохранение.
- Критерии приемки: Восстанавливаются монеты, шкалы, инвентарь.
- Метод проверки: тест.

**REQ-FUNC-010 — Валидация сохранения**
- Утверждение: Система должна проверять файл сохранения на корректность.
- Критерии приемки: При некорректном файле — сообщение или запуск с нуля.
- Метод проверки: тест.

**REQ-FUNC-011 — Golden Pet**
- Утверждение: Система должна с заданной вероятностью создавать редкого Golden Pet, начислять бонус и показывать анимацию.
- Критерии приемки: при срабатывании Golden Pet игрок получает бонус; анимация отображается; событие логируется.
- Метод проверки: тест.

**REQ-FUNC-012 — Звуковое сопровождение**
- Утверждение: Система должна воспроизводить звуковые эффекты для событий (клик, кормление, достижение) без блокировки UI.
- Критерии приемки: звук воспроизводится при событии; UI не блокируется; звук можно отключить в настройках.
- Метод проверки: демонстрация.

### 3.3 Качество обслуживания

**REQ-PERF-001 — Время запуска**
- Утверждение: Приложение должно запускаться не более чем за 3 секунды.
- Метод проверки: Тестирование, Анализ.

**REQ-PERF-002 — Отзывчивость интерфейса**
- Утверждение: После клика или действия интерфейс обновляется без заметной задержки.
- Метод проверки: Тестирование, Демонстрация.

**REQ-PERF-003 — Память**
- Утверждение: приложение должно занимать не более 200 МБ памяти.
- Метод проверки: профилирование.

**REQ-REL-001 — Сохранение после закрытия**
- Утверждение: После штатного закрытия последние данные доступны для загрузки.
- Метод проверки: Тестирование.

**REQ-REL-002 — Обработка ошибок сохранения**
- Утверждение: Ошибки чтения/записи обрабатываются без сбоев.
- Метод проверки: Тестирование.

**REQ-REL-003 — Версионирование сохранения**
- Утверждение: файл сохранения содержит версию формата (`schemaVersion`); при несовпадении выполняется миграция.
- Метод проверки: тест.

**REQ-REL-004 — Однопоточность таймеров**
- Утверждение: все таймеры работают в UI-isolate; фоновые isolate не используются.
- Метод проверки: инспекция кода.

### 3.4 Соответствие стандартам

**REQ-COMP-001 — Уникальные идентификаторы требований**
- Утверждение: каждое требование имеет уникальный идентификатор.
- Метод проверки: инспекция.

**REQ-COMP-002 — Согласованность ссылок**
- Утверждение: ссылки на мокапы и модель соответствуют файлам в репозитории.
- Метод проверки: инспекция.

### 3.5 Сопровождение

**REQ-MAINT-001 — Изоляция domain-слоя**
- Утверждение: `domain` не импортирует `package:flutter`.
- Метод проверки: архитектурный тест.

**REQ-MAINT-002 — Покрытие тестами**
- Утверждение: покрытие `domain` unit-тестами ≥ 80 %.
- Метод проверки: CI (`flutter test --coverage`).

**REQ-MAINT-003 — Обновление UI**
- Утверждение: UI обновляется через `ChangeNotifier`; прямые `setState` из domain запрещены.
- Метод проверки: ревью.

**REQ-MAINT-004 — Логирование ошибок**
- Утверждение: ошибки сохранения/загрузки логируются в `debugPrint`; в релизе отключено.
- Метод проверки: ревью.

**REQ-MAINT-005 — CI**
- Утверждение: сборка и тесты запускаются в CI на каждый push; артефакт — APK.
- Метод проверки: проверка CI.
